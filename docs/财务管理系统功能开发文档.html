1.1 目的与范围

  • 本文档规定财务管理系统各功能的开发规格，是开发、联调、测试与验收的依据；

1.2 术语

术语说明

02

通用开发约定

所有功能遵循的统一规范，开发前必读

2.1 统一返回体与分页

// 统一返回体
{ "code": 200, "msg": "ok", "data": { ... } }
// 分页请求：page=1&size=10
// 分页返回：{ "records": [...], "total": 100, "page": 1, "size": 10 }

业务错误码：400 参数错误、401 未登录、403 无权限、409 业务冲突（如期间已结账）、500 系统异常。

2.2 公共字段与状态枚举

类别值说明
公共字段create_by / create_time / update_by / update_time / deleted所有业务表统一携带；deleted 为逻辑删除
单据通用状态 statusDRAFT 草稿 / APPROVING 审批中 / APPROVED 已通过 / REJECTED 已驳回 / CLOSED 已关闭需审批单据（报销/合同/工资/付款）统一使用
凭证状态DRAFT 草稿 / AUDITED 已审核 / BOOKED 已过账 / REVERSED 已冲销凭证专用状态机
金额NUMERIC(18,2)前端用字符串/分传递，后端 BigDecimal，禁止 float

2.3 权限注解与数据权限

  • 接口权限：Controller 方法加 @PreAuthorize("hasAuthority('finance:voucher:add')")，权限码 = 模块:资源:操作；
  • 数据权限：查询列表时通过 MyBatis-Plus 拦截器，按当前用户数据范围自动追加 WHERE department_id IN (...) 或 create_by = ?；
  • 写操作统一记录操作日志（模块、动作、单据号、内容摘要、IP、时间）。

2.4 多公司（公司编码）约定

  • 模型：一套代码、一套数据库（共享库），多家公司用 company_code 区分，公司之间完全独立、数据互不可见、无合并报表需求；
  • 公司档案：新增 sys_company 表（company_code 唯一 / 公司名称 / 纳税识别号 / 启用状态）；
  • 字段贯穿：所有业务表统一新增 company_code VARCHAR(20) NOT NULL + 联合索引；凭证唯一约束 = (company_code, period, voucher_no)；
  • 上下文：登录绑定所属公司，后端 ThreadLocal 携带 company_code，所有查询自动按公司过滤；
  • 独立性：凭证号（公司+期间+序列）、期间结账（fin_period 带公司）、科目（每公司一套，支持模板复制）、三大报表均按公司独立；
  • 隔离兜底：核心财务表启用 PostgreSQL RLS 按 company_code 过滤（SQL 漏写也不串号）；Flowable 流程实例 tenantId = 公司编码；附件 MinIO 路径前缀 company_code/。
03

系统管理功能

登录、用户、角色、菜单、字典、日志

3.1 登录认证

/api/auth/login · POSTP0
业务规则
  • 账号密码登录，密码 BCrypt 校验；连续 5 次失败锁定 15 分钟；
  • 成功返回 JWT（有效期 2h）+ 用户信息 + 权限码集合 + 数据范围；
  • 前端路由守卫校验 token，过期跳登录页。
数据/接口
表sys_user / sys_role / sys_user_role
接口POST /auth/login、POST /auth/logout、GET /auth/profile
权限公开（无需登录）

3.2 用户 / 角色 / 菜单管理

/api/system/user|role|menuP0
业务规则
  • 用户 CRUD、分配角色（多选）、重置密码、启用/停用；
  • 角色 CRUD、给角色分配菜单/按钮权限点（树形勾选）；
  • 菜单：目录/菜单/按钮三级，按钮权限码形如 finance:voucher:add；
  • 删除保护：已被用户/子菜单引用的角色与菜单禁止删除。
数据/接口
表sys_user / sys_role / sys_user_role / sys_role_menu / sys_menu
接口GET/POST/PUT/DELETE /system/user、/role、/menu
权限system:user:list/add/edit/del（仅管理员）

3.3 字典管理 · 操作日志

/api/system/dict|logP0
业务规则
  • 字典类型 + 字典数据两级维护，供下拉选项（合同类型、费用类型、单据状态等）；
  • 字典缓存 Redis，变更后主动失效；
  • 操作日志只增不删，记录关键写操作；查询支持按模块/操作人/时间过滤。
数据/接口
表sys_dict_type / sys_dict_data / sys_operation_log
接口GET/POST /system/dict；GET /system/log
权限system:dict:*、system:log:list
04

财务管理功能（核心）

科目、凭证、账簿、结账、报表、报销、收付款、凭证映射引擎

4.1 会计科目管理

/api/finance/subjectP0
业务规则
  • 科目按编码层级树形展示（如 1002 银行存款 / 100201 银行存款-工行）；
  • 科目属性：类别（资产/负债/权益/成本/损益）、借贷方向、是否末级、辅助核算项（部门/客户/供应商/合同勾选）；
  • 末级科目才能记账；已有发生额科目禁止删除/改编码，可停用；
  • 提供期初余额导入（Excel 模板，仅首个会计期间可导入）。
数据/接口
表fin_account_subject、fin_balance_initial（期初）
接口GET /subject/tree、POST /subject、PUT /subject/{id}、DELETE /subject/{id}、POST /subject/import
权限finance:subject:add/edit/del/import（会计及以上）

4.2 凭证管理（录入/审核/过账/冲销）

/api/finance/voucherP0
业务规则
  • 凭证号 = 期间 + 序列（seq_voucher_no），保存即占用且不可重复；
  • 录入校验：借贷合计必须相等、金额>0、末级科目、辅助核算必填校验；数据库 CHECK 兜底；
  • 状态流转：DRAFT(可编辑/删除) → 审核 AUDITED → 过账 BOOKED(只读) → 冲销生成红字凭证；
  • 已审核/已过账凭证禁止直接修改；过账后如需更正走红字冲销 + 蓝字重录；
  • 来源：手工录入或业务单据自动生成（source_type 标识）。
数据/接口
表fin_voucher / fin_voucher_entry（借贷平衡 CHECK + 期间凭证号唯一）
接口GET/POST /voucher、PUT /voucher/{id}/audit、/book、/reverse、DELETE /voucher/{id}(草稿)
权限finance:voucher:add/edit(会计)；audit(财务经理/会计)；book/reverse(财务经理)

4.3 账簿查询

/api/finance/bookP0
业务规则
  • 支持总账、明细账、日记账三种视图，按期间 + 科目筛选；
  • 总账按科目汇总期初/本期发生/期末；明细账逐笔列示凭证分录；
  • 数据来源为已过账凭证；支持导出 Excel。
数据/接口
表fin_voucher / fin_voucher_entry（按期间聚合）
接口GET /book/{type}?period=&subjectId=
权限finance:book:list

4.4 期末结账

/api/finance/period/closeP0
业务规则
  • 结账前置校验：期间无未审核/未过账凭证、借贷平衡、试算平衡（资产=负债+权益）；
  • 结账后该期间凭证只读、禁止新增；再次结账需先反结账（仅管理员/财务经理）；
  • 损益结转：自动生成"本年利润"结转凭证（可配置）；
  • 期间表记录结账人、结账时间。
数据/接口
表fin_period（期间状态）/ fin_voucher
接口PUT /period/close、PUT /period/reopen、GET /period/list
权限finance:period:close/reopen（财务经理）

4.5 财务报表（三大报表）

/api/finance/reportP0
业务规则
  • 资产负债表、利润表、现金流量表，按期间生成；
  • 报表取数来自已过账凭证按科目汇总；资产负债表校验资产=负债+权益；
  • 支持按月度/年度、含期初/期末列；导出 Excel；驾驶舱用 ECharts 展示趋势。
数据/接口
数据fin_voucher_entry 按科目/期间聚合 + 科目性质映射
接口GET /report/balance-sheet、/income、/cash-flow
权限finance:report:list（会计及以上）

4.6 费用报销

/api/finance/expenseP1
业务规则
  • 员工提交报销单（类型、事由、金额、发票号、附件），DRAFT 可撤回；
  • 提交流程：DRAFT → 审批中 → 部门负责人审批 → 财务审核 → 打款 → 已打款；驳回可重新提交；
  • 财务审核校验：发票合规、预算可用（若启用预算）；
  • 打款后发布事件 → 凭证引擎自动生成费用凭证（借 费用科目 / 贷 银行存款）；
  • 已打款报销单不可删改。
数据/接口
表fin_expense_claim / fin_expense_item / 附件表
接口GET/POST /expense、PUT /expense/{id}/submit、/approve、/reject、/pay
权限发起(员工)；审批(部门负责人)；审核/打款(财务)

4.7 收付款与应收应付

/api/finance/payment|receivableP1
业务规则
  • 应收应付来源：合同收付款计划自动生成 或 手工登记；
  • 出纳登记收款/付款单（关联应收应付、银行账户）→ 核销（支持部分核销、一单核销多笔）→ 回写来源单据状态；
  • 核销后发布事件 → 凭证引擎生成资金凭证；
  • 账龄 = 当前日期 − 应收应付到期日，按 0-30/31-60/61-90/90+ 分档展示与预警。
数据/接口
表fin_receivable_payable / fin_payment_receipt / fin_bank_account
接口GET/POST /receivable、/payment、PUT /payment/{id}/confirm(核销)、GET /receivable/aging
权限登记/核销(出纳)；查看/确认(财务经理)

4.8 凭证映射引擎（核心）

fin_voucher_rule + 事件监听P1
业务规则
  • 规则配置：单据类型 + 条件（如费用类型）→ 借方科目 / 贷方科目 / 辅助核算项，财务管理员维护；
  • 触发：业务单据审批通过/核销完成 → 发布 BusinessDocApprovedEvent（sourceType/sourceId/金额/辅助信息）；
  • 引擎：监听事件 → 匹配规则 → 组装分录 → 写入凭证草稿（DRAFT）→ 来源回填；
  • 幂等：source_type + source_id 唯一约束，重复事件不重复生成；
  • 异常：未匹配规则时记录失败日志并提醒财务，走手工凭证兜底。
数据/接口
表fin_voucher_rule / fin_voucher / fin_voucher_entry
接口GET/POST /voucher-rule；事件发布在业务 Service 内
权限规则维护(财务经理)；触发为系统内部
开发要点：引擎为无状态组件，入参为标准事件对象，便于单测；先内置固定模板（报销/合同收付款/工资/社保），复杂规则二期扩展。

合同管理功能

台账、审批、收付款计划、到期提醒

5.1 合同台账

/api/contractP0
业务规则
  • 登记：合同编号（自动生成）、类型（采购/销售/服务/租赁）、签约方、合同金额、起止日期、经办人、附件；
  • 状态流转：草拟 → 审批中 → 生效 → 履约中 → 已完成 / 已终止；
  • 生效后自动按合同条款生成收付款计划；到期前 30 天进入提醒范围；
  • 删除保护：已审批/已生效合同不可删除，只能作废。
数据/接口
表ct_contract / ct_contract_attachment
接口GET/POST /contract、PUT /contract/{id}、POST /contract/{id}/submit、/void
权限维护(合同管理员/业务)；审批走流程

5.2 合同审批（按金额分级）

Flowable 流程P0
业务规则
  • 流程：提交 → 部门负责人 → 财务审核（收付款条款）→ 分级审批（≤10万止步部门+财务；10-100万加分管领导；>100万加总经理）→ 生效；
  • 任一节点驳回则流程结束，单据回 DRAFT 可修改重提；
  • 审批通过回调：合同状态=生效 → 生成收付款计划 → 发布事件联动财务。
数据/接口
表wf_instance / wf_task + ct_contract.status
接口POST /contract/{id}/submit；GET /workflow/todo、POST /workflow/task/{id}/approve|reject
权限按流程节点角色；分级金额可配置

5.3 收付款计划

/api/contract/{id}/payment-plansP0
业务规则
  • 合同生效自动生成计划（期次、金额、计划日期、方向 收/付），可手工微调（需留痕）；
  • 到期 → 自动生成应收/应付单（去重幂等）→ 收付款核销后回写"已收/已付金额、状态"；
  • 提供计划执行进度视图（已收付/计划比例）。
数据/接口
表ct_contract_payment_plan → fin_receivable_payable
接口GET /contract/{id}/payment-plans、POST /contract/{id}/payment-plans
权限finance:receivable:list（财务）/ contract:plan:edit（合同管理员）

5.4 到期提醒

定时任务P1
业务规则
  • 每日定时：合同到期前 30 天提醒经办人；收付款计划前 7 天提醒责任人；应收逾期每日标记；
  • 提醒渠道：站内消息 + 首页待办；点击待办跳转对应单据；
  • 提醒记录幂等（按 单据+日期+类型 去重）。
数据/接口
表sys_message / 定时任务扫描 ct_contract、ct_contract_payment_plan、fin_receivable_payable
接口GET /todo/list、GET /message/list、PUT /message/{id}/read
权限登录用户查看本人

人事管理功能

部门、员工档案、考勤、工资核算与工资条

6.1 部门与员工档案

/api/hr/employee|departmentP0
业务规则
  • 部门：树形（支持两级即可），维护部门负责人（用于审批默认节点与数据权限）；
  • 员工：工号唯一、姓名、部门、岗位、入职日期、劳动合同到期日、联系方式、状态（在职/离职）；
  • 离职员工停用账号，历史数据保留；劳动合同到期前 30 天提醒 HR；
  • 数据权限：HR 全量，部门负责人仅本部门，员工仅本人（档案只读）。
数据/接口
表base_department / hr_employee
接口GET/POST /hr/department、/hr/employee、PUT /hr/employee/{id}/status
权限hr:employee:add/edit（HR）；查询按数据权限

6.2 考勤管理

/api/hr/attendanceP1
业务规则
  • 月度考勤：出勤天数、请假天数（事假/病假）、加班天数，支持批量导入或逐人录入；
  • 考勤结果供工资核算取数（请假扣款、加班工资）；
  • 员工仅查看本人；HR 全量。
数据/接口
表hr_attendance（员工+月份 唯一）
接口GET/POST /hr/attendance、POST /hr/attendance/import
权限hr:attendance:edit（HR）

6.3 工资核算与工资条

/api/hr/salaryP0
业务规则
  • 工资项：基本工资 + 考勤调整（扣款/加班）+ 社保个人部分 − 个税 = 实发；个税按累计预扣法计算（内置税率表）；
  • 流程：草稿 → 批量计算 → 提交审核（HR）→ 财务复核 → 已发放；
  • 发放后发布事件 → 凭证引擎生成工资费用凭证（借 管理费用-工资 / 贷 应付职工薪酬，发放时借 应付职工薪酬 / 贷 银行存款）；
  • 工资条：员工自助查看本人当月条，仅本人可见；
  • 数据权限：HR 全量，财务复核可见，员工仅本人工资条。
数据/接口
表hr_salary（员工+月份 唯一）、社保表（单位/个人金额）
接口POST /salary/calculate、GET /salary/list、POST /salary/{id}/submit、/approve、/pay；GET /salary/{id}/slip
权限核算(HR)；复核(财务)；slip(本人)
07

公共支撑功能

审批流、消息通知、附件、定时任务

7.1 审批流（Flowable 封装）

  • 统一 WorkflowService：start(业务类型, 业务单号)、todo(用户)、approve(taskId, 意见)、reject(taskId, 意见)；
  • 流程节点绑定「角色 + 数据范围」，任务实时取审批人；支持退回、加签、会签（一期先做单人顺序审批）；
  • 审批完成回调：通过 → 更新业务状态 + 发布事件；驳回 → 单据回草稿。

7.2 消息通知 · 附件 · 定时任务

能力规格
消息通知站内消息（sys_message）+ 首页待办（todo 聚合：审批待办、提醒）；已读/未读
