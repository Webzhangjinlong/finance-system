一

开发约束（5 类硬规则）

所有约束必须有"可执行载体"——写进 AGENTS.md、测试、lint、DB CHECK 或 CI，禁止只停留在文档描述

1.1 业务硬约束（Business Invariants）

这些是财务系统的"不可破坏规则"，任何代码变更都不得违反。每条都必须有对应测试或数据库约束兜底。

约束规则可执行载体
必须金额精度 所有金额字段一律 NUMERIC(18,2)；后端用 BigDecimal；前端用字符串传递；禁止 float/double 存金额 DB 字段类型 + 代码检查 + 单测
必须多公司隔离 所有业务表必须携带 company_code；任何查询必须带公司过滤；禁止跨公司数据查询；公司之间无合并需求 MyBatis-Plus 拦截器 + PG RLS + 单测
必须凭证借贷平衡 每张凭证借方合计 = 贷方合计；分录金额 > 0；末级科目才能记账；数据库 CHECK 兜底 fin_voucher CHECK + 单测
必须凭证状态机 DRAFT → AUDITED → BOOKED → REVERSED；已审核/已过账凭证禁止直接修改；改错走"红字冲销 + 蓝字重录" 状态枚举 + 状态流转单测
必须凭证号唯一 凭证号 = 公司 + 期间 + 序列；并发下不重号不跳号；唯一约束 (company_code, period, voucher_no) DB 唯一约束 + 序列 + 并发测试
必须期间结账 已结账期间凭证只读、禁止新增；反结账仅财务经理；结账前校验借贷平衡、无未过账凭证、试算平衡 fin_period 状态 + 结账校验单测
必须凭证生成幂等 同一业务单据重复触发不生成第二张凭证；以 source_type + source_id 唯一约束 DB 唯一约束 + 幂等测试
应当核销规则 支持部分核销、多单核销一笔；核销后回写来源单据状态；账龄按剩余未核销金额 + 到期日计算 核销单测
应当工资计算 个税按累计预扣法；应发 − 社保个人 − 个税 = 实发；工资条仅本人可见 个税计算单测 + 权限测试
红线：以上"必须"级约束，任何 PR 违反一律 CI 失败、禁止合入。

1.2 架构与分层约束

约束规则可执行载体
必须分层依赖Controller → Service → Mapper，禁止 Controller 直连 Mapper、禁止 Service 反向依赖 Controller、禁止跨业务域直接调 Mapper（跨域走 Service 接口）ArchUnit 架构测试
必须技术栈固定前端 Vue3+Element Plus+ECharts；后端 Spring Boot 3(JDK17)+MyBatis-Plus；DB PostgreSQL 16；缓存 Redis 7；审批 Flowable 7；存储 MinIOpom.xml/package.json 锁定版本
必须模块化单体后端按 finance-system/finance-finance/finance-contract/finance-hr/finance-workflow/finance-common/finance-framework 分包，不拆微服务目录结构 + ArchUnit
应当事务边界资金类操作（收付款、凭证生成、工资发放）必须 @Transactional + 幂等键；跨域事件用 Spring Event 解耦，不直接强耦合代码审查 + 集成测试
应当统一返回所有接口返回 Result<T>（code/msg/data）；分页返回 records/total/page/size；错误码 400/401/403/409/500全局异常处理器 + 单测

1.3 代码与命名约束

项规则
后端命名类：大驼峰（XxxController/XxxService/XxxMapper）；方法：小驼峰；常量：全大写下划线；包：全小写
前端命名组件：大驼峰 .vue；composable：useXxx；store：小驼峰；API 文件：按模块 xxx.js
数据库表名：模块前缀_业务名（fin_voucher/ct_contract/hr_employee）；字段：小写下划线；主键 id；公共字段 create_by/create_time/update_by/update_time/deleted
接口路径/api/{模块}/{资源}，RESTful 风格；权限码 = 模块:资源:操作（finance:voucher:add）
日志关键写操作记录操作日志（模块/动作/单据号/IP/时间）；禁止日志输出密码、token、身份证等敏感信息
注释复杂业务规则（凭证生成、个税、结账）必须写注释说明规则来源；公共方法写 Javadoc
魔法值状态、类型、错误码必须用枚举或常量，禁止硬编码字符串/数字

1.4 数据库约束

  • 主键：BIGINT GENERATED ALWAYS AS IDENTITY，禁止业务主键；
  • 金额：NUMERIC(18,2)；
  • 时间：TIMESTAMP WITH TIME ZONE；
  • 公共字段：所有业务表带 create_by/create_time/update_by/update_time/deleted（逻辑删除）；
  • 公司编码：所有业务表带 company_code VARCHAR(20) NOT NULL + 联合索引；
  • 核心 CHECK：凭证借贷平衡、金额 > 0、状态枚举合法；
  • 唯一约束：凭证号(公司+期间+号)、公司编码、员工工号、用户账号；
  • RLS：核心财务表启用行级安全，按 company_code 过滤（SQL 漏写也不串号）；
  • 迁移：所有表结构变更走 Flyway/Liquibase 迁移脚本，禁止手工改库。

1.5 安全与权限约束

  • 认证：JWT 登录，有效期 2h；密码 BCrypt 加密；连续 5 次失败锁定 15 分钟；
  • 授权：RBAC + 数据权限（全部/本部门/本人/本公司）；接口必须加 @PreAuthorize；
  • 数据权限：列表查询通过 MyBatis-Plus 拦截器自动注入过滤，禁止业务代码硬编码绕过；
  • 输入校验：所有接口参数用 @Valid + JSR-303 注解；禁止拼接 SQL（用参数化）；
  • 敏感数据：身份证、手机号、银行卡脱敏展示；密码、token 禁止出现在日志/响应；
  • 关键操作：付款、结账、反结账、凭证冲销需记录审计日志，且需对应角色权限；
  • 文件上传：限制类型/大小，病毒校验，存储 MinIO 按 company_code 前缀隔离。
二

Codex + Harness 完整流程

从项目初始化到日常开发、验证、收敛的标准化工作流，智能体按此流程执行

2.1 项目初始化流程（一次性，约 0.5 天）

1
建仓库与脚手架

Git 初始化；前后端脚手架（Vue3 Vite + Spring Boot Initializr）；Docker Compose（PG16/Redis7/MinIO）

2
落 Harness 文件

写入 AGENTS.md（~100 行导航）、docs/（三份文档 + business-rules.md + architecture-rules.md + openapi.yaml）、.harness/ 四件套、.codex/skills/ 五个 Skill

3
建库与种子数据

执行 DDL 建表；插入 demo 公司、科目模板、示例凭证、测试账号；验证启动可跑

4
配 CI 门禁

.github/workflows/ci.yml：lint → 单测 → 契约测试 → 构建 → 覆盖率门禁（≥70%）

5
冒烟验证

用 Codex 跑一个最小任务（如"新增一个字典项"），验证 AGENTS.md 被读取、命令可执行、CI 通过

完成标志：Codex 能独立完成一个 CRUD 任务，且全程自动遵守 AGENTS.md 约束、CI 全绿。

2.2 日常任务开发流程（每个任务）

1
任务拆解

把需求拆成可独立验证的小任务（每个任务 ≤ 1 天）；明确验收标准（对应哪条业务约束/哪个接口）

2
读上下文

Codex 自动读 AGENTS.md；按需读 docs/ 对应文档、business-rules.md、相关 Skill；禁止凭记忆写代码

3
编码实现

按分层约束写代码；硬约束必须遵守（金额类型、company_code、状态机）；复杂工作流调用对应 Skill

4
自跑验证

本地执行 AGENTS.md 中列出的 test/lint/build 命令；财务正确性用例必须通过；失败则修复并重跑

5
自审（/review）

调用 code-review Skill 自审：是否违反约束、是否有硬编码、是否缺测试、是否有安全问题

6
提交 PR

写清晰 commit message（类型+模块+说明）；PR 描述关联需求与验收标准；触发 CI

7
CI 门禁

CI 全绿才可合入；失败则回到第 4 步；关键操作（付款/结账）需人工 review

纪律：Codex 不得跳过自跑验证和 /review 直接提交；不得在 CI 失败时强行合入。

2.3 技能（Skill）调用流程

高频复杂工作流封装为 Skill，Codex 按场景显式（$skill-name）或隐式（按描述匹配）调用：

Skill触发场景核心步骤
voucher-engine新增/修改凭证生成逻辑、单据→凭证映射读映射规则 → 组装分录 → 幂等校验 → 写草稿 → 来源回填 → 跑凭证测试
period-close期末结账/反结账功能开发校验未过账凭证 → 借贷平衡 → 试算平衡 → 结转损益 → 锁定期间 → 结账测试
company-onboard新增公司/多公司初始化建公司档案 → 复制科目模板 → 录期初 → 建账号权限 → 验证公司隔离
db-migration表结构变更写 Flyway 迁移脚本 → 保留数据 → 验证回滚 → 更新 rule-registry
code-review提交前自审检查硬约束 → 检查测试覆盖 → 检查安全 → 检查命名 → 输出问题清单

2.4 验证门禁（CI）流程

1
代码检查

后端 checkstyle/spotbugs；前端 eslint/prettier；不通过即失败

2
架构测试

ArchUnit 校验分层依赖、命名规范、禁止跨层调用

3
单元测试

业务硬约束用例（借贷平衡、凭证号并发、幂等、结账校验、company_code 隔离）；覆盖率 ≥ 70%

4
集成测试

Testcontainers 起真实 PG；验证事务、审批流回调、收付款联动

5
契约测试

OpenAPI 契约校验：前后端接口字段一致

6
构建

前后端构建成功；产物可部署

门禁规则：任一步骤失败，PR 禁止合入；不得用 --no-verify 或跳过 CI 绕过。

2.5 收敛反馈流程（持续改进）

1
发现失败

Codex 犯错（测试失败、评审发现问题、线上 bug）→ 记录现象

2
复盘

填写 .harness/failure-review.md：目标/失败现象/根因/避免方法/需新增的规则

3
登记教训

在 .harness/lessons.md 新增条目：错误→根因→固化载体→状态（待固化/已固化）

4
固化规则

把教训变成可执行规则：更新 AGENTS.md / business-rules.md / 新增测试 / 修改 Skill / 加 lint 规则

5
更新总账

.harness/rule-registry.md 登记新规则：来源→载体→验证机制→版本

6
收敛检查

定期跑 .harness/check.md：待固化=0？规则无缺口？AGENTS 覆盖硬约束？直到结构幂等

收敛目标（结构幂等）：lessons 中"待固化"为 0，rule-registry 全覆盖，重新应用规则不再产生新变化——此时同一错误不会再犯第二次。

2.6 多 Agent 协作分工（可选，复杂任务启用）

角色职责配置要点
default（主控）任务拆解、协调、最终提交读 AGENTS.md，分配子任务
explorer（调研）读文档、查代码、确认接口/表结构，输出调研报告只读权限，不写代码
worker（开发）按调研结果编码、写测试、自跑验证沙箱限制，只能改指定模块
monitor（监督）盯测试结果、CI 状态、硬约束违反，告警只读，发现问题通知 default

配置位置：~/.codex/config.toml 开启 multi_agent = true，每个角色配独立 instruction、模型、sandboxing。

2.7 精确命令清单（AGENTS.md 中必须列出，Codex 直接执行）

# 后端
cd finance-server
./mvnw test                    # 单元测试
./mvnw verify                  # 全量验证（含架构测试）
./mvnw spring-boot:run         # 启动后端
./mvnw checkstyle:check        # 代码风格检查

# 前端
cd finance-web
npm install
npm run lint                   # 代码检查
npm run test                   # 前端测试
npm run dev                    # 启动前端
npm run build                  # 构建

# 环境
docker compose up -d           # 启动 PG/Redis/MinIO
docker compose down            # 停止环境

# 数据库迁移
cd finance-server
./mvnw flyway:migrate          # 执行迁移
./mvnw flyway:info             # 查看迁移状态
命令必须在脚手架搭建后验证可执行；不可执行的命令不得写入 AGENTS.md。

3.1 AGENTS.md 完整模板（仓库根目录，~100 行）

# 财务管理系统 AGENTS.md

## 项目
业财一体的多公司财务系统，覆盖财务管理、合同管理、人事管理三模块。
业务单据（报销/合同收付款/工资）审批后自动生成记账凭证。

## 技术栈
- 前端：Vue 3 + Vite + Pinia + Element Plus + ECharts
- 后端：Spring Boot 3 (JDK 17) + MyBatis-Plus + Spring Security + JWT
- 数据库：PostgreSQL 16（金额 NUMERIC(18,2)，禁止 float）
- 缓存：Redis 7；审批：Flowable 7；存储：MinIO
- 部署：Docker Compose + Nginx

## 目录结构
- finance-web/       前端
- finance-server/    后端（按 system/finance/contract/hr/workflow/common/framework 分包）
- docs/              知识库（三份文档 + 提取规则 + OpenAPI）
- .codex/skills/     项目级技能
- .harness/          收敛文件（lessons/registry/review/check）

## 硬约束（写代码前必读 docs/business-rules.md）
1. 金额一律 NUMERIC(18,2)，后端 BigDecimal，禁止 float/double
2. 所有业务表必须携带 company_code，禁止跨公司查询
3. 凭证必须借贷平衡；状态机 DRAFT→AUDITED→BOOKED→REVERSED
4. 凭证号 = 公司+期间+序列，唯一约束 (company_code, period, voucher_no)
5. 已结账期间凭证只读；改错走红字冲销+蓝字重录
6. 接口必须带 @PreAuthorize 权限注解；数据权限由拦截器自动注入
7. 分层：Controller→Service→Mapper，禁止跨层、禁止 Controller 直连 Mapper
8. 状态/类型/错误码必须用枚举，禁止硬编码

## 命令
- 后端测试：cd finance-server && ./mvnw test
- 后端全量验证：cd finance-server && ./mvnw verify
- 前端检查：cd finance-web && npm run lint
- 启动环境：docker compose up -d
- 启动后端：cd finance-server && ./mvnw spring-boot:run
- 启动前端：cd finance-web && npm run dev

## DO NOT
- 不要用 float/double 存金额
- 不要跨公司查询数据
- 不要修改已结账期间的凭证
- 不要绕过权限注解或数据权限拦截
- 不要跳过测试和 /review 直接提交
- 不要用 --no-verify 绕过 CI 门禁
- 不要在日志输出密码、token、身份证

3.4 CI 配置示例（.github/workflows/ci.yml）

name: CI
on: [pull_request, push]
jobs:
  backend:
    runs-on: ubuntu-latest
    services:
      postgres: { image: postgres:16, env: { POSTGRES_PASSWORD: test }, ports: ['5432:5432'] }
      redis: { image: redis:7-alpine, ports: ['6379:6379'] }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '17' }
      - run: cd finance-server && ./mvnw checkstyle:check        # 步骤1 代码检查
      - run: cd finance-server && ./mvnw test -P archunit        # 步骤2 架构测试
      - run: cd finance-server && ./mvnw verify                  # 步骤3+4 单测+集成
      - run: cd finance-server && ./mvnw package -DskipTests     # 步骤6 构建
  frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: cd finance-web && npm ci && npm run lint           # 前端检查
      - run: cd finance-web && npm run test -- --coverage       # 前端测试
      - run: cd finance-web && npm run build                    # 前端构建
  contract:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npx @redocly/cli lint docs/api-contracts/openapi.yaml  # 步骤5 契约校验
覆盖率门禁：后端 JaCoCo ≥ 70%，前端 Vitest 覆盖率 ≥ 60%；财务核心模块（凭证/结账/收付款）覆盖率 ≥ 85%。
